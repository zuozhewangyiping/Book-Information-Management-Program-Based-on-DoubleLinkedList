# 基于双向链表的图书信息管理

C 语言课程实践项目一。用一条双向链表存放图书（书号、书名、价格），通过命令行菜单完成建表、调价、
找最贵、入库、出库、去重，以及自选的排序与逆序共 8 项操作。

- 语言标准：C11（`-std=c11`）
- 环境：Windows + MSYS2 UCRT64 的 `gcc`（GCC 16.1.0）
- 源码编码：UTF-8

## 功能一览

| 编号 | 功能 | 对应函数 | 来源 |
| --- | --- | --- | --- |
| ① | 创建并输出图书信息表 | `task_create` | 题目要求 |
| ② | 按平均价格调整书价 | `task_modify` | 题目要求 |
| ③ | 查找价格最高的图书 | `task_most_expensive` | 题目要求 |
| ④ | 新图书入库 | `task_insert` | 题目要求 |
| ⑤ | 旧图书出库 | `task_erase` | 题目要求 |
| ⑥ | 图书去重（按书号） | `task_dedup` | 题目要求 |
| ⑦ | 按价格排序（升序/降序） | `task_sort` | 自选扩展 |
| ⑧ | 逆序存储 | `task_reverse` | 自选扩展 |

题目要求 6 项，⑦⑧ 是在要求之外增加的扩展功能。

## 编译与运行

### 一键构建（推荐）

双击 `build.bat`。它会调用 `build.ps1`，依次完成：检测终端代码页 → 选择字符集 → 编译
`books.exe` → 在同一个窗口里直接运行。

- `build.bat`：编译并运行
- `build.bat build`：只编译不运行

编译前会检查四个源文件是否齐全、`gcc` 是否在 PATH 中；任何一步失败都会打印原因并以非 0 退出，
不会启动旧程序。

### 手动编译

四个源文件必须一起编译（`DoubleLinkedList.c` 提供 `library.c` 用到的全部容器函数）。
在代码页为 936 的终端里：

```powershell
# PowerShell
gcc -std=c11 -Wall -Wextra -pedantic -O2 -fexec-charset=GBK main.c library.c book_io.c DoubleLinkedList.c -o books.exe; if ($LASTEXITCODE -eq 0) { .\books.exe }
```

```bat
rem cmd
gcc -std=c11 -Wall -Wextra -pedantic -O2 -fexec-charset=GBK main.c library.c book_io.c DoubleLinkedList.c -o books.exe && books.exe
```

代码页为 65001 的终端（VS Code、Windows Terminal）去掉 `-fexec-charset=GBK`。
四种组合（PowerShell / cmd × 936 / 65001）见 [编译指令.txt](编译指令.txt)。

## 使用说明

启动后进入菜单，输入编号后按提示输入数据：

1. 每本图书一行：`书号 书名 价格`，用空格分隔；书名内部可以有空格和括号
   （解析时取第一个字段为书号、最后一个字段为价格，中间部分整体作为书名）。
2. 书单以单独一行 `0 0 0` 结束。
3. 位置序号从 1 开始：入库合法范围是 `1 ~ n+1`，出库是 `1 ~ n`。
4. 价格统一保留两位小数输出。
5. 菜单输入非法时提示「无效选项」并回到菜单；输入流结束（EOF）时直接退出。

示例：

```
请选择：1
请输入书单，以 0 0 0 结束：
9787302257646 程序设计基础 25.00
9787302164340 程序设计基础(第 2 版) 20.00
0 0 0
2
9787302257646 程序设计基础 25.00
9787302164340 程序设计基础(第 2 版) 20.00
```

完整的输入与期望输出见 [测试样例.txt](测试样例.txt)。

## 设计说明

### 为什么选双向链表

- 题目要求用线性表，顺序表和链表都可以；这里选链式存储。
- 头尾插入、删除都是 O(1)，入库/出库不需要搬动元素。
- 「逆序存储」只需交换每个节点的 `next` 和 `prev` 指针，不复制数据，O(n) 且不额外分配内存。

### 容器接口

- 结构体定义完全隐藏在 `.c` 里，对外只有不透明的 `DoubleLinkedList` / `DoubleLinkedListNode`。
- 所有操作返回 `int`：`1` 成功、`0` 失败，游标起始函数额外用 `-1` 表示空表，便于调用方区分
  「空表」和「出错」。
- 遍历通过游标 API 完成：`node_begin` / `node_next` / `node_get_data`，另有一套 `_mut` 版本
  用于修改元素。两套分开，避免遍历时误改数据。

### 所有权与深拷贝

- 元素中的书名是 `char *`，容器在插入或写入时深拷贝一份，元素与链表各管各的内存。
- 调用方负责释放自己的临时元素：`push_back` / `insert` 之后调用 `ELEMENT_DESTROY`。
- 任何函数失败时都不会把只构造了一半的元素挂进链表。

### 排序

自底向上迭代归并排序：宽度从 1 开始倍增，每轮把相邻两段就地合并。

- 链表上只改指针，不需要随机访问，也不需要额外数组；
- 稳定：价格相同时保持原有相对顺序（升序用 `<=`、降序用 `>=` 比较）；
- 迭代实现不递归，规模增大也不会爆栈。

`collation == 1` 升序，其它值降序。

### 去重

按书号去重，保留第一次出现的记录。外层逐个节点，内层扫描它后面的节点，发现相同书号就删除后者，
复杂度 O(n²)，在本项目的数据规模下足够。

### 输入解析

先在原行上确定书号、书名、价格三段的下标区间，再按区间拷贝，因此书名里的空格、括号都能原样
保留。书号固定校验 13 个字符。

`build.bat` 会自动检测当前终端的代码页并选择对应的选项，日常使用不必关心这一点；只有手动执行
`gcc` 时才需要按上表选择。

## 已知限制

- 书号固定 13 个字符，长度不符的输入行按格式错误处理。
- 去重为 O(n²)，数据量很大时效率会下降。
- 未做大数据量压力测试，验证规模在几十本图书。
- 目前只在 Windows + MinGW 工具链上验证。
